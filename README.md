# FastAPI 中文文档问答助手

基于 FastAPI 官方中文文档构建的 RAG（检索增强生成）问答服务。用户输入 FastAPI 相关问题后，系统检索对应文档片段，生成带出处的回答；当检索结果不足以支撑作答时，按规则拒答。

## 核心功能

- **文档切分与向量检索**：收录 122 篇 FastAPI 中文文档，按 500 字 / 重叠 100 字切分为 1,093 个文本块；使用 `BAAI/bge-small-zh-v1.5` ，默认采用纯向量检索（保留 BM25 与 RRF 混合检索作为可选项）。
- **带出处生成与拒答**：接入 DeepSeek API，约束模型仅依据检索到的片段作答并标注来源编号 `[n]`；无相关依据时统一回复「文档中没有找到相关内容」。
- **Web 接口与异常处理**：基于 FastAPI 提供 `/ask` 接口，启动时预加载模型与向量，包含参数校验、错误码映射（400 / 422 / 502）及文件日志记录；调用 DeepSeek 时对 5xx、超时和连接错误自动重试。
- **离线评估体系**：区分开发集（51 题）、保留测试集（36 题，与开发集无文档重叠）、无答案测试集（10 题）、代码名回归集（13 题）与歧义题（8 题），跟踪文档级/块级 Hit@5、拒答率、误拒率与引用支持率。
- **问答历史**：`/ask` 的每次请求（正常、拒答、400、502）都写入 SQLite（问答表 + 出处表，同一事务写入），提供 `GET /history` 按条数和是否拒答查询；写库失败只记日志，不影响回答。
## 评估结果（保留测试集，方案冻结后只跑一次）

| 指标 | 结果 |
|---|---|
| 文档级 Hit@5 | 27/36（开发集 42/51） |
| 块级 Hit@5 | 22/36 |
| 换说法题拒答 / 原词题拒答 | 8/18 / 1/18 |
| 引用文档命中率 | 43/48 |
| 无答案题拒答 | 10/10（其中 1 道为无效题） |

## 运行

1. 安装依赖：

   ```bash
   pip install -r requirements.txt
   ```

2. 复制 `.env.example` 为 `.env`，填入自己的 DeepSeek API Key
3. 启动服务：

   ```bash
   fastapi dev api.py
   ```

4. 打开 http://127.0.0.1:8000/docs ，可以直接在网页上测试接口

### 查询历史

请求：

```
GET /history?limit=5&refused=true
```

返回：

```json
[
  {
    "id": 2,
    "created_at": "2026-11-25T14:43:15",
    "question": "Fastapi中mamba有什么用",
    "answer": "文档中没有找到相关内容",
    "refused": true,
    "status": 200,
    "error": null
  }
]
```
## 状态码

| 状态码 | 说明                                                     | 日志级别 |
|-----|--------------------------------------------------------|---|
| 200 | 正常返回；查不到时 `refused` 为 true，回答为「文档中没有找到相关内容」            | INFO |
| 400 | question 去掉空格后为空                                       | WARNING |
| 422 | 请求体缺 question 字段或类型不对；或 `/history` 的 limit 超出 1～100（在进入接口函数之前就被拦下） | 不记录 |
| 502 | 调用 DeepSeek 失败：5xx、超时重试 3 次仍失败，或 4xx（如 Key 无效）         | ERROR |

## 已知局限

1. **示例代码未入库**：FastAPI 中文文档里展示代码的位置是指向 `docs_src/` 的占位符，而不是代码正文。例如询问如何查看 `root_path` 时，关键代码 `request.scope.get("root_path")` 在独立的 `.py` 文件里，模型拿不到，只能给出较浅的回答。可改进方向：入库时把占位符替换成对应 `.py` 文件的内容，再重新切块、向量化，并重跑开发集。
2. **检索漏块后的否定式断言**：开发集中有一题询问何时用 `async def`、何时用普通 `def`，由于关键块 `async.md#1` 没有被检索到，模型直接断言「资料中没有给出明确判断标准」。这种说法比明确拒答更容易误导用户。统计开发集 36 道作答题，只有 1 道出现这类表述，因此暂未修改 Prompt；可改进方向是把表述限定为「检索到的资料中未提及」，并在开发集上回归验证。
3. **测试集文档长度分布偏差**：开发集按块随机抽样，天然偏向篇幅较长的文档（平均 12.8 块/篇）；排除开发集文档后，保留测试集来自较短的文档（平均 6.9 块/篇），两者分布不同。
4. **测试集规模与独立性**：36 道题来自 18 块原文，原词题和换说法题成对出题，并不独立；测试集只跑了一次，无法得知大模型回答的波动有多大；10 道无答案题中有 1 道是无效的占位题。
5. **引用支持率抽查样本偏小**：15 道作答题共 34 个引用，判为支持 31、部分支持 3、不支持 0（91%）。其中 27 个由大模型辅助判定、7 个人工判定；人工抽查了大模型判定的 6 个，5 个一致，但抽查前看过其判定，不算独立复核。
